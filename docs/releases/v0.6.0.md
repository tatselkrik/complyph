# ComplyPH 0.6.0 — Source update checks

Approve official publication URLs, check them daily while ComplyPH is open, and inspect downloaded changes without sending private documents online.

- Add per-source URL approval, daily/due scheduling and **Check approved sources now**. No URL is enabled by default; source import and URL approval remain separate.
- Preserve changed response bytes, hashes, origins, download dates and review records. Earlier references, downloaded versions and saved report citations remain available. Failed checks retain the last successful state.
- Add **Update review needed** filtering, visible change flags, download export and source-review notes. Downloading or reviewing a change does not automatically change curated reference text or checking rules.
- Add a separate packaged updater with a Windows AppContainer network worker, InternetClient capability, an explicit inherited-handle list, protected runtime code and job-based limits/lifetime. The worker verifies isolation before networking and cannot open synthetic private-store, catalog or original-document canaries.
- Enforce HTTPS agency domains, public DNS addresses, same-origin redirects, TLS validation, bounded responses and credential-free GET requests. Other-platform builds keep networking disabled.
- Migrate the public catalog to schema 4 while retaining private schema 3 and `C:\ProgramData\ComplyPH`. Upgrade/reinstall/uninstall preserve data and original files.

Close ComplyPH before installing. The complete portable ZIP includes `complyph-updater.exe`; keep it beside `ComplyPH.exe`. Normal use needs no command prompt, AI model, account or API key. Windows binaries remain unsigned.

These checks inspect selected URLs; they do not discover every new law, infer legal amendments or automatically update the three labour checking rules. In-app OCR, watched folders and other-domain rules remain planned. Checksums and machine-readable Windows installation/isolation evidence accompany the packages.
